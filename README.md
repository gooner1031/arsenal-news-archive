# arsenal-news-archive
## 移籍トラッカーの品質管理
- `tools/test_tracker.py` … 過去の誤判定（ヴィニシウスの否定報道、スコット/クルピの取りこぼし、ムドリクの過去発言、スビメンディ本人の否定、クルピの括弧内「オファー」）の回帰テスト。判定ロジック（index.html の trBuild / TR_RX / trCtx）を触ったら必ず実行。
- `tools/promo.py` … サイト自体の宣伝・告知ポスト（サイトの URL・サイト名・「ホーム画面に追加」・CONTACT の案内・「このアカウントで毎日発信」など）の判定。自動取得（fetch_x.py）で除外し、毎日の正式タグ付けでも同じ判定を使う。目印のない告知は `tools/promo_ids.txt` に ID を追記。回帰テストは `tools/test_promo.py`。
- `tools/post_rule.py` … 自動取得で載せるポストの判定。引用RP・URL・画像/動画・出典表記（【媒体】/（@媒体））つきと、そのスレッドの続きだけ載せ、他人へのリプライ・私的な一言・宣伝は除外。既存データには適用しない。
- 本人・クラブの否定は「インタビュー・コメント」等のポストに入っていても、トラッカーに載っている選手なら破談・停滞として反映する。
- `tools/audit_transfers.py` … 直近の移籍ポストに出る未登録の選手名を `pending_players.json` に出力（毎時の fetch-x で自動更新）。候補は確認のうえ `tools/people.py` と meta.json に追加。
- 判定は「その選手が出てくる文（見出しなら次の文まで）」だけで行う。投稿全体で判定しない。

## 試合前のスタメン発表（lineup.json）
- `tools/lineup.py` が ESPN の公開データ（試合ごとの summary の rosters。非公式・キー不要）からアーセナルのスタメン11人とベンチを取り、`lineup.json` に書く。手で編集しない。
- `.github/workflows/lineup.yml` が15分ごとに起動し、次の試合（next.json）がキックオフ80分前以内のときだけ、発表まで2分ごとに確認する（キックオフ20分後まで）。それ以外は数秒で終わる。
- 選手名は meta.json の people / academy.json の英語表記（`e`）に合わせる（アクセント違い・「Gabriel」のような省略形も照合）。合わない名前は ESPN の表記のまま入る。
- 配置（フォーメーション図）は ESPN の formationPlace（背番号の慣習どおり 1=GK 2=右SB 3=左SB 4・5・6=中央 7=右 8=中央 9=CF 10=トップ下 11=左）と formation の文字列から決める目安。試合前のデータにはポジション略号が `D``M``F` 程度しかないため。配置の作り方を変えたら `LAYOUT` を上げると、試合前なら lineup.json を作り直す。
- サイトでは次の試合と一致する間だけ、ホームとマッチ情報に「STARTING XI 発表されたスタメン」を出す（index.html の `luBox()`）。試合が終わると自動で消え、試合後のスタッツ（matchstats.json）に切り替わる。
- 通知：リポジトリの Secrets に `NTFY_TOPIC` を入れると、取り込んだときに ntfy.sh へ送る（無料・登録不要）。スマホの ntfy アプリでそのトピック名を購読すると届く。トピック名は推測されにくい文字列にする。
- 過去の試合で取り込みを試す：`python3 tools/lineup.py --event <ESPNの試合番号> --league eng.1`（書き込み・通知なし）。

## ホーム上部の「直近の試合」（試合後24時間）
- ホームの「今日のアーセナル」の一番上は、試合終了から24時間は直近の試合（結果）、それ以降は次の試合。直近の試合を出している間、次の試合は下の1行（日時・あと何日）になる（index.html の `tdRecent()`）。
- 24時間の起点は、試合後の更新で `season.json` の `results` に入れる `ft`（試合終了・日本時間 `"YYYY-MM-DDTHH:MM"`）。結果を入れるときは、upcoming にあった `jst`（キックオフ）も一緒に残す。
  - 例：`{"d":"2026-11-24","c":"チャンピオンズリーグ","ha":"H","o":"ドルトムント","sc":"…","r":"…","nt":"","jst":"2026-11-25T05:00","ft":"2026-11-25T06:54"}`
  - `ft` がないときは `jst`＋115分（`nt` に「延長」「PK」があれば＋150分）、それもなければ「日程・結果」が main に入った時刻（updated.json の `fixtures`）で代用する。
- 次の試合のキックオフが6時間以内なら、24時間以内でも次の試合を優先する。
- ネタバレ防止モードでは、ほかの画面と同じくスコアと勝敗を「スコアを表示」で隠す（タップで表示）。

## 試合スタッツ
- `tools/match_stats.md` … matchstats.json の項目と、試合後に追加するベンチ（`bench`）・欠場者（`abs`）の取り方。欠場者は試合時点で確認できたものだけ入れる。
- 公式MOM：`potm`＝大会公式（PL・UEFA）、`potmA`＝アーセナル公式（arsenal.com・公式アプリの投票）。公式発表がなければ空のまま（推測で埋めない）。試合ページとホームの「直近の試合」に表示し、試合日から3日は「発表待ち」。詳細は `tools/match_stats.md` の「公式MOM」。

## アカデミーの今季成績
- `tools/academy_stats.md` … academystats.json（アカデミー選手ページの出場・先発・途中・ゴール）の出典と追加のしかた。公式の試合レポートを読んで手で数える（自動取得はしない）。



## 文字サイズ（小・標準・大）
- メニューとフッターの「文字サイズ」で切替。選択は `localStorage` の `ana-fz`（`s`＝小 / `l`＝大、なし＝標準）。
- 文字の大きさは `font-size:calc(13px*var(--fz,1))` の形で書く（`--fz` は小 0.9・標準 1・大 1.2）。新しく px で文字サイズを書くときもこの形にすると設定が効く。

## 出典・最終更新・訂正履歴
- 各データ画面の下に「出典・最終更新・訂正・更新履歴・間違いを指摘」の1行を出す（index.html の `dsrc('<キー>')`）。
- 最終更新は手書きしない。`tools/stamp.py` がデータごとの中身の変化を見て、main に入った時刻（日本時間）を `updated.json` に書く。main への push のたびに `.github/workflows/stamp.yml` が自動で実行する。
- 新しいデータ画面を足すときは `tools/stamp.py` の `SECTIONS` に1行（キー・ファイル・取り出し方・表示名・出典）を足し、画面で `dsrc('<キー>')` を呼ぶ。出典の文言もここで直す。
- 間違いを直したら `corrections.json` の先頭に1件足す：`{"d":"YYYY-MM-DD","k":"訂正|更新","t":"日本語","en":"English","p":["選手の英語名"],"h":"関連ページのハッシュ"}`（`p`・`h` は任意）。「訂正・更新履歴」ページ（#corrections）に新しい順で出る。

## 読み込みの速さ（ホームの初期表示）
- ホームは `posts-new.json`（posts.json の直近60日分）だけで先に描画し、そのあと `posts.json` → `posts-old.json` の順に読み込んで合流する。ホーム以外から開いたときは最初から全ポストを読む。
- `posts-new.json` は手で編集しない。`tools/split_posts.py` が posts.json から作る。posts.json が main に入ると `.github/workflows/posts-new.yml` が自動で作り直す（fix-cut.yml でも作り直す）。ずれていても、posts.json が届いた時点で正しい内容に置き換わる。
- 最初に使うデータは `<head>` で先読み（preload）している。ファイル名を変えるときは index.html の先読みの一覧も合わせて直す。

## 検索（ヘッダーの検索欄・#search）
- 表記ゆれは `fz()` で吸収する（全角半角・ひらがな/カタカナ・ヴ→ブ・ティ→チ・ディ→ジ・ズ/ヅ→ス・シュ→ス・小さい文字・長音・促音・＝・アクセント付きの英字）。ポスト側の検索用テキスト（`pn()`）も同じ形で、表示後の空き時間に作る。
- 選手・記者・媒体・クラブは日本語名・英語名・別表記のどれで入れても、そのタグの付いたポストと、日本語表記を含むポストに当たる。よくある別表記（ヨケレス、エーデゴール、富安など）は index.html の `SALIAS` に足す。
- 入力中は人物・記者・媒体・クラブ・カテゴリの候補を出し、選ぶと絞り込み条件（チップ）になる。
- 絞り込み：人物・記者・媒体・クラブ（複数可）、期間（1週間〜1年・日付指定・シーズン）、ポストの種類（カテゴリ・画像付き・スレッド）、移籍（IN/OUT・段階・移籍市場）。移籍は移籍トラッカーと同じ集計（`trBuild`）を、使ったときだけ作る。
- ネタバレ防止モードの隠し方はほかの一覧と同じ（`card()` → `spPost`）。候補リストにはスコアを出さない。

## シェアカード（Xなどに貼ったときの画像）
- 移籍トラッカーの各選手・試合・人物のページにある「Xでシェア」「共有／リンクをコピー」は、サイト本体ではなく共有ページ `s/<ハッシュ名>.html`（例 `s/tr-18-2027W.html`・`s/match-pl20261107.html`・`s/person-1.html`）のURLを渡す。Xのクローラーは `#` 以降を見ないため、こうしないと全部トップの og.png になる。共有ページは開くとすぐサイトの該当ページへ移る。
- 共有ページと画像（`s/img/`、1200×630）は `tools/share_cards.py` が作る。移籍の段階・試合結果はサイトと同じ判定（`trBuild` など）をブラウザで動かして取る。画像は直近の移籍市場・直近2シーズンの試合・全人物だけで、それ以外は og.png。中身が変わったカードだけ描き直し、画像のファイル名も変わる（Xの古いキャッシュを避けるため）。
- posts.json・meta.json・transfers.json・index.html・share_cards.py が main に入ると `.github/workflows/share-cards.yml` が自動で作り直す。手で動かすときは `pip install playwright pillow && python3 -m playwright install chromium` のあと `python3 tools/share_cards.py`（デザインを変えたら自動で全部描き直す。`--force` で強制）。
- ネタバレ防止モードで結果を隠している試合は、シェア文にスコアを入れず、スコアなしのカード `s/match-<id>-ns.html` を使う。
- URL末尾の `?v=` は移籍の段階・結果の有無。変わるとXがカードを取り直す。
- まだ共有ページがない（追加直後など）URLは `404.html` がサイトの該当ページへ移す。

## 公式X用の投稿文の下書き（自動投稿はしない）
- 移籍トラッカーの段階が「合意」「完了」になったとき（直近3日以内の報道）と、試合の結果（スコア）が入ったとき（試合日が直近3日以内）に、投稿文の下書きを `drafts.json` に足す。作るのは `tools/post_drafts.py`（シェアカードと同じ `share-cards.yml` の中で動く）。
- 下書きは `drafts.html`（サイトからはリンクしていない管理用ページ。https://gooner1031.github.io/arsenal-news-archive/drafts.html ）で見る。「Xで投稿」でX の投稿画面が文面とリンク入りで開く。リンクはシェアカードの共有ページなので画像が付く。
- 試合はスコア入りと、ネタバレなし（スコアなし・`-ns` のカード）の2案を出す。
- 一度下書きにした出来事は `drafts.json` の `seen` に記録し、二度作らない。下書きは新しい順に40件まで残す。
- 文面を変えるときは `tools/post_drafts.py` の `tr_draft` / `m_drafts` を直す。X の文字数（全角2・URL 23）で280を超えるときは説明の行から削る。

## 次の試合ウィジェット・カレンダー登録（widget.html）
- `widget.html` … 次の試合（対戦相手・キックオフの日本時間とイギリス時間・カウントダウン）と、その後の4試合だけを出す軽いページ。メニューの「WIDGET」と、次の試合カードの下の1行から開く。ホーム画面に追加すると「次の試合」として単独で開く（`widget.webmanifest`）。テーマ・文字サイズ・言語はサイト本体の設定（`ana-theme` / `ana-fz` / `ana-lang`）をそのまま使う。`?embed` を付けると試合部分だけになる（ブログなどへの埋め込み用）。
- カレンダー購読：`fixtures.ics`（日本語）・`fixtures-en.ics`（英語）。登録するとスマホのカレンダーアプリとカレンダーのウィジェットに試合が出る。スコアは入れない。キックオフ未定の試合は終日の予定にする。
- iPhone のホーム画面・ロック画面ウィジェット：`widget-scriptable.js`（無料アプリ Scriptable 用）。`next.json` を読む。ウィジェットの Parameter に `en` で英語。Parameter に `clear` で透過風の背景（`en,clear` も可）。iPhone は本当の透過ができないので、アプリ内で実行 →「透過の背景を設定」でホーム画面のスクショ（アイコンが揺れている状態の空のページ）を選ぶと、ウィジェットの位置を切り出して `ana-widget-bg-<大きさ>-<light|dark>.jpg` として Scriptable の書類フォルダに保存する。ライト/ダークは `Device.isUsingDarkAppearance()` で選び、`light` / `dark` で固定もできる。切り出し位置の表（`PHONES`、キーはスクショの高さ px）は mzeryck/Widget-Blur（MIT）の値。新しい iPhone は表に足す。
- `next.json`・`fixtures.ics`・`fixtures-en.ics` は手で編集しない。`tools/widget_data.py` が season.json の `upcoming` から作る。season.json が main に入ると `.github/workflows/widget.yml` が自動で作り直す。英語のクラブ名は index.html の英語表記の辞書（`CL`）から取るので、新しい相手の英語名はそこに足す。

## マッチデーページ（次の試合の詳細）
- MATCH PREVIEW は直近10日の関連ポストのうち、未読（NEW）の中からいいね数の多い順に2件だけ出す。未読が2件に満たないときは既読のいいね上位で補う。
- season.json の `next.oppForm`（相手の直近5試合）には各試合に大会名 `c`（例：`ブンデスリーガ`・`DFBポカール`・`チャンピオンズリーグ`）を必ず入れる。バッジの略称は index.html の `COMPS`（BL・LL・SA・L1・DFB杯など）。`c` がない試合は、相手がプレミアのクラブのときだけ PL を付け、それ以外はバッジを出さない。

## スコア予想・選手採点・MOTM投票（worker/・vote-api.json）
- 試合前：マッチ情報（#matchinfo）でスコアとアーセナルの得点者（最大3人）を予想。得点者の候補はトップチーム全員（GK含む）で、スタメン・ベンチが発表（lineup.json）されたらその18人前後だけに絞る（サーバーも外れた選手の新規送信を断る。すでに選んでいた人は外れ扱いのまま、予想カードに「どんまい」と出し、サイトのポストから拾った、ちょっと笑えるひと言（`PVDM`・6件）とクイズのミス用の励まし（`QW_RESET`・18件）を日替わりで添える。英語表示は日本語ポストからの訳である旨を併記）。キックオフの24時間前から受付（それより前は「予想は◯月◯日 ◯:◯◯（日本時間）から」と案内。サーバーも拒否する）、キックオフで締切、それまでは何度でも上書き。みんなの予想はキックオフ後に公開。ホームの次の試合カードの下に、受付中で未予想の人にだけ小さな吹き出し「予想に参加」を出し、タップでマッチ情報の予想カードへ（予想済みは「予想済み ✓」）。試合後も同じ仕組みで、ホームの「前の試合」の下に、採点の受付中（試合終了から12時間）で採点かMOTMが未了の人にだけ「採点に参加」の吹き出しを出し、タップで試合ページの採点カードへ（両方済みは「採点済み ✓」）。
- 試合後：キックオフ115分後を試合終了とみなし、そこから12時間、出場選手と監督の採点（1〜10点・0.5刻み。6を基準にしたスライドバーと＋−。付けたい人だけでよく、未採点のままで送信できる。監督はMOTMの対象外）とMOTM（1位3点・2位2点・3位1点）を受け付ける。直しは最初の送信から1時間以内に1回だけ。みんなの平均・順位は自分が送信すると見られ、30秒ごとに更新（LIVE）。受付終了後は誰でも見られる。試合ページ（#match-… / #mx-…）と、受付中はマッチ情報の下にも出る。
- 平均は、選手ごとに中央値から3点以上離れた票と、5人以上に全員同じ点を付けた採点を除いて計算。採点の平均は3票から表示し、予想の的中率は10人から表示する。予想の的中は matchstats.json のスコア（アーセナルが先）と得点者で判定するので、試合データが入るまで結果は出ない。
- 採点の対象は matchstats.json のスタメン＋途中出場。まだなければ lineup.json のスタメン＋ベンチ。
- ネタバレ防止モードで隠している試合は、予想の結果・採点・MOTMをまとめて隠す（自分の予想だけ見える）。
- 集計サーバーは `worker/`（Cloudflare Workers + D1、無料枠）。ルールは `worker/src/logic.js`、テストは `cd worker && node --test test/logic.test.mjs`。1端末1票（ブラウザの `ana-dev`）、同じ回線から1試合20端末まで。IPは保存せず、秘密の値と混ぜた元に戻せない値だけ持つ。
- 公開：リポジトリの Secrets に `CLOUDFLARE_API_TOKEN`（テンプレート「Cloudflare Workers を編集する」＋ D1 編集）と `CLOUDFLARE_ACCOUNT_ID` を入れると、`worker/` が main に入るたびに `.github/workflows/worker.yml` がデータベース作成・公開を行い、公開先 URL を `vote-api.json` に書く。`vote-api.json` の url が空のあいだ、サイトには何も表示されない。手で公開し直すときは Actions の worker を「Run workflow」。

## 今日のアーセナル（ホーム上部の1画面まとめ）
- ホームの一番上に、次の試合（日本時間・英国時間・あと何時間）、前の試合（試合日から2日以内だけ）、新着ニュース、移籍の動き（直近7日に報道があった選手）、今日は何の日、今日が誕生日の人を1つの箱で出す。index.html の `tdBox()`。
- 新着ニュースは「前回の訪問からの新着」（なければ直近24時間）から、いいねの多い順に3件を選んで新しい順に並べる。ここに出したポストはすぐ下の LATEST では重ねて出さない（`TD_IDS`）。
- ネタバレ防止モードでは、前の試合のスコアと勝敗を隠し（`spV`）、結果に触れていそうなポスト（`spPost`）は新着・今日は何の日に出さない。
- 英語表示では、見出しを posts-en.json の英訳 → 端末の翻訳キャッシュ → 自動翻訳の順で差し替える（`window.enPost`）。
- これまでホームにあった大きな次の試合カード・「前回の訪問から○件の新着」・「移籍トラッカーで○人に動き」・誕生日の帯は、この箱にまとめた（日程・マッチ情報のページの次の試合カードはそのまま）。

## 推しフィード（#feed・ホームの「MY FEED」）
- お気に入り選手（`ana-fav-players-v1`、この端末だけに保存）のタグが付いたポストを新しい順に出す。ホームは「今日のアーセナル」の下に最新3件（ネタバレ防止中は結果に触れていそうなポストを出さない）、専用ページ `#feed` は全件と選手ごとの絞り込み。入り口はメニューの「MY FEED」・ホームの箱・お気に入りページ。
- 未読は `ana-seen` の `fav`（フィードを最後に見た時刻）より新しく、かつその選手をお気に入りにした後のポスト。未読があるとメニューに赤い点。
- お気に入りが0人のときは、直近60日でポストの多いアーセナルの選手を「☆」ボタンで出し、その場で追加できる。
- ホームの箱はメニューとフッターの「ホームの推しフィード」で表示しないにできる（`localStorage` の `ana-home-feed` = `off`、`<html data-fdh>`）。表示しないでも専用ページ `#feed` とメニューの入り口は残る。0人のときの案内にも「箱推しなのでホームに表示しない」ボタンを出す。

## 今日のクイズの難易度（★1〜3）
- 問題は毎日ブラウザで自動で作る（index.html の `QGEN` の問題の型から日付で選ぶ）。保存された問題の一覧はない。難易度は問題を作るときに `qMk` の最後の引数で付ける。
- 内容の基準：★1 初級＝直近の試合（今季）や現役選手の基本（背番号・今季加入選手の前所属）／★2 中級＝過去数シーズン（1〜3季前）の試合・記録や移籍（前所属）、1年前の今日は何の日／★3 上級＝歴史（4季以上前・2年以上前の今日は何の日）や細かい記録（出場数・契約年）。シーズンは7月始まりで数える（`qLvD`）。
- 回答が50人（`QLV_MIN`）以上集まったら、みんなの正答率で付け直す（70%以上＝★1、40〜70%＝★2、40%未満＝★3。`qLvRate`）。
- ★は問題カードの上・回答後のカード・Xシェアの文面に出る。新しい問題の型を足すときは上の基準で★を渡す。

## クイズの連続正解のひと言
- 今日のクイズに答えたあと、連続正解数 N と同じ背番号にまつわる言葉を出す（index.html の `QW`）。不正解で連続正解が0になったときは励ましのひと言（`QW_RESET`）。
- 言葉は3種類：その番号の現役選手本人の言葉（`k:'o'`）、現役選手に向けた監督・仲間・家族などの言葉（`k:'t'`、`by` が話し手）、過去にその番号を付けていた選手の言葉（`k:'p'`、`no` がその番号）。1つの番号に5件までで、回答回数で日替わり。
- 言葉はサイトのポストから手で選ぶ。基準：感謝・喜び・決意・ファンや仲間への言葉など前向きなもの、70字目安。負傷・批判・判定への不満・移籍の噂・試合結果が分かる内容は入れない。言い回しはポストのまま。英語は日本語からの訳。
- 必ず出典を出す：話し手（人物ページへのリンク）・ポストの日付・ポスト内の出典・サイトのポスト（X）へのリンク、元記事のURLがポストにあればそれも。
- `o`・`t` の背番号は profiles.json から引くので、退団・番号変更は自動で反映される。N にひと言がないときはいちばん近い番号（同じ距離なら小さい方）。60を超えたら全員から日替わり。
- 不正解時の `QW_RESET` は慰め・前を向く・反省を促す言葉を18件（ミスがいちばん多いので多めに）。
- 背番号の主な歴代選手（`QWH`、1993年以降）も出す。記事に「その番号を付けた」とある選手だけを、出典（`QWH_SRC`）つきで載せる。ひと言がない番号は、近い番号のひと言の代わりに歴代選手のカードを出す。
- 新しい選手が来たら `QW` に足す（`e` は profiles.json / meta.json の英語名）。過去の番号（`k:'p'`）は、その選手がその番号を付けていたシーズンを確認してから足す。
